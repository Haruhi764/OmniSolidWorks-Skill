# SolidWorks V0.4 专项验收

2026-11-24（北京时间）。实机为 SolidWorks 2014 x64 SP0，COM `22.0.0`。A、B 的零件与装配沿用已通过的原生产物，本轮只复验二维图纸。

| 案例 | 结论 | 验收结果 |
| --- | --- | --- |
| A 轴、轴承环、套筒和紧固件 | PASS | 5 组件、6 配合、4 步。原装配检查点已复用。A3 工程图保存、关闭、重开，4 个视图和 5 行 BOM、5 个序号匹配，实际预览中的序号均在图框内。 |
| B 壳体、端盖、轴和紧固件 | PASS | 5 组件、4 配合、4 步。两紧固件同一步移动，端盖 Z +25 mm、X +120 mm。A3 工程图保存、关闭、重开，4 个视图、4 行 BOM 和 4 个序号匹配，紧固件数量为 2。实际预览已确认原有越界问题修复。 |

原生装配变换在爆炸、折合、保存重开后复核，两个案例的最终包络各检查 10 对。工程图先保存布局检查点，再保存正式 SLDDRW 和导出 PDF、DWG、DXF。最终 PDF 逐案渲染为 180 DPI 的 PNG，以 SHA-256 绑定实际导出和视觉记录。A 有一处引出线交叉，序号和端点可辨。设计、签章和工艺批准字段留空。

## COM 故障复盘

- Windows 记录 `swccu.dll` 偏移 `0x18a0`，异常 `0xc0000005`。前一轮 COM 证据中，搬移的原生装配检查点由 `OpenDoc6` 成功打开并返回重建警告 32，随后重建前的查询阶段出现 `RPC_E_SERVERFAULT`。日志不足以区分该阶段的具体故障方法。已有修复将重建移到查询前。
- 更早的 `sldapiu.dll` 访问违规对应爆炸线草图退出试验。该路径已撤下。最终两次工程图作业使用同一实例，各自串行关闭全部自有文档，两个作业结束时文档计数均为 0。
- 空白基线工作集约 325 MiB、专用内存约 239 MiB，系统可用物理内存约 3.64 GiB。A 后为 569 / 464 MiB，B 后为 632 / 731 MiB。已知记录指向旧版原生模块访问违规，内存采样不足以证明崩溃成因。
